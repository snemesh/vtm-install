# VTM — установщик

Живая 3D-карта инфраструктуры: серверы, приложения, сайты и запросы между ними. Ставится одной командой на Docker-хост или в Kubernetes-кластер и сама находит, что там работает.

```bash
curl -fsSL https://raw.githubusercontent.com/snemesh/vtm-install/main/install.sh | sh
```

Сайт с описанием: https://snemesh.github.io/vtm-install/

**Через ИИ-агента:** скажите Claude Code в своём проекте — «Поставь VTM на этот проект по инструкции https://snemesh.github.io/vtm-install/agent.md». Инструкция для агента — [AGENTS.md](AGENTS.md).

Установщик определяет, что на машине — Docker или доступ к кластеру (`kubectl`), проверяет сервер, ставит готовые образы `ghcr.io/snemesh/vtm-collector` и `vtm-map` (amd64, arm64) и печатает адрес карты и пароль.

| Параметр | Что делает |
|---|---|
| `--docker` / `--kubernetes` | выбрать, если доступно и то и другое |
| `--version 0.3.0` | конкретный выпуск (по умолчанию самый новый) |
| `--port 8091`, `--bind 0.0.0.0` | Docker: порт и адрес карты (по умолчанию `127.0.0.1`: только сам сервер, снаружи — SSH-туннель) |
| `--expose ingress=<host>` / `loadbalancer` / `nodeport` | Kubernetes: открыть карту в сеть (по умолчанию `none`: `kubectl port-forward`) |
| `--set key=value` | Kubernetes: любое значение чарта, например `storage.className=fast` |
| `--check` | только проверить, что карта увидит здесь |
| `--uninstall` | удалить VTM и его данные (на Docker-хосте — через `sudo sh`) |
| `--help` | список параметров |

Параметры передаются так: `curl -fsSL …/install.sh | sh -s -- --kubernetes`.

Повторный запуск обновляет установку; пароль сохраняется.

Карта работает по HTTP, поэтому по умолчанию она не открыта в сеть. Для доступа извне ставьте перед ней обратный прокси с HTTPS. Служебные порты на сервере закрыты правилом файрвола `VTM-GUARD`; в Kubernetes хранилища пускают только с токеном стека. Beyla ничего не дописывает в трафик приложений. Данные (метрики, логи контейнеров за 30 дней, трассы запросов с путями) хранятся у вас и наружу не уходят.
